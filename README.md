# URL Shortener

## Особенности реализации

- Данные созданных коротких ссылок кешируются в Redis - это снижает нагрузку на БД. Кеш инвалидируется при удалении записи из БД с помощью события Eloquent;
- Переходы по ссылкам регистрируются после отправки ответа клиенту (через terminating middleware) - это ускоряет выдачу редиректа;
- Логика получения данных ссылки, инвалидации кеша и регистрации переходов вынесена в сервисы - есть минимальный Service Layer;
- Реализованы feature-тесты для проверки соответствия ТЗ;
- Проект локализован для русского языка, в том числе ошибки валидации;
- Проект упакован в Docker для удобства развертывания.

## Как развернуть?

В корне проекта:
```bash
cp .env.example .env && docker-compose up -d
```

Проект будет доступен по адресу ```http://localhost:8000```

## Как можно улучшить?

- Перенести регистрацию переходов по ссылкам из middleware в очередь на базе RabbitMQ (проект - продюсер, отдельный сервис - консьюмер), на консьюмере вычитывать и записывать переходы батчами. Это снизит нагрузку на БД;
- Отказаться от использования Eloquent в сервисах и реализовать паттерн "Репозиторий". Это позволит писать изолированные Unit-тесты на сервисы;
- Полнотекстовый поиск в списках ссылок / переходов (```searchable()```) - не эффективно. Можно интегрировать Sphinx;
- Не в рамках репозитория - инфраструктурные работы: балансировщики нагрузки, репликация и шардирование БД.
